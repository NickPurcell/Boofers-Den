  • Protocol: went from v1.0 to v1.3. The Rust and Java codecs are byte-identical across about 900 cross-checked frames, and the Java codec was written from the spec alone.

What held up:

  • the hybrid passthrough with its ownership split;
  • the custom bridge instead of the MC protocol;
  • native entities instead of an overlay;
  • spike first and contract first;
  • parallel tracks with one integration lane.

The six spike questions were the right six. Everything the build corrected is folded into the sections below, marked Field note.

02Verdict

VIABLE · BUILT

Viable, and now demonstrated. First-person Steve in Night City, a creative hotbar with every item, blocks you can stand on that the path tracer lights, and creepers that Maelstrom shoots and that blow Maelstrom up. Four real limits apply (see the end).

Cyberpunk is an easier host than Elden Ring. Single player has no anti-cheat. The modding stack is mature: CET, RED4ext with Rust bindings, Codeware, TweakXL and ArchiveXL. Existing mods already spawn solid props and hostile NPCs at runtime.

03How the viral ones were built

There are three different recipes behind the clips:

  • 01 / 03

    Full rewrite (chasm’s MW2 × Skate 3 × Minecraft). All three games are AI-written Rust rewrites in one Bevy process (mashup repo, a fork of IW4L). This is the “Rust rewrite” Nick heard about: MinecraftOSS, about 131k lines traced from decompiled Java, vendored but not published separately. Its mobs only target the player. The route needs a Rust rewrite of the host game, and nobody has one for Cyberpunk, so it isn’t an option here.

  • 02 / 03

    Passthrough (chasm’s Skyrim). Real Minecraft and real Skyrim run side by side, with a mod in each: Minecraft things are passed into Skyrim’s renderer, and collision is fed back (explainer). No code is public, and the clip shows no Minecraft mobs.

  • 03 / 03

    Tobyn Jacobs’ Elden Ring and DS1. These mod the real games and were built with a multi-agent setup around Opus 5.5 (post). The architecture hasn’t been disclosed; our Elden Ring study finds the footage likely real.

Prior art for Cyberpunk: Khoner4504/mc-cyberpunk was public on 29 Sep with a passthrough design (Paper server plus a Rust RED4ext plugin speaking the MC protocol via Azalea), and gone by that evening. It never got past a placeholder box.

04Architecture: hybrid passthrough

Ownership. Minecraft is authoritative for blocks, redstone, items, mob decisions and mob HP. Cyberpunk owns the terrain, its NPCs, V, and every body you see. Real Java Minecraft is the only way to get every mob, all items and full redstone (pistons included), and it runs alongside path tracing on 2–4 GB and 1–2 cores.

Why a custom bridge instead of speaking the MC protocol. Vanilla sends mob movement only about every 150 ms. A Fabric mod can snapshot every tick (50 ms) with exactly the fields we need. Cyberpunk renders 75–100 ms behind and interpolates. Block edits are predicted locally and confirmed by the server.

  • Field note: TCP loopback, not a named pipe. Java has no clean full-duplex on a single Windows named-pipe handle. TCP loopback is in the same latency class, and it also runs in Linux CI.

Coordinates. One block is one metre, which is Cyberpunk’s unit. A fixed anchor maps the MC origin to a spot in Night City.

  • Field note: scope to Northside. The headline clip needs Maelstrom, and Maelstrom’s turf is Northside, not Kabuki or Little China. Northside’s terrain voxelizes in 152 s.
  • Field note: vertical quantization. Voxel ground lands at ceil(surface), so on a street at z 18.2 blocks floated 0.8 m. A CP-side render offset fixes it (anchor z −0.8).

05The pieces

Blocks are native entities, not an overlay. A block is a spawned entity with a cube mesh (Minecraft textures upscaled so they stay crisp) and a box collider, as entSpawner does. That gets path tracing, correct depth, DLSS and frame-gen motion vectors, and a floor V can stand on. A D3D12 overlay would lose all of that. Only exposed blocks are spawned, neighbouring solid blocks are merged into large colliders, and entities are pooled because spawning is asynchronous.

  • Field note: blocks are nearly free. On screen, 2k / 5k / 10k blocks change frame time by −1.0 / −1.5 / −2.0 ms, because they hide more expensive geometry behind them. Off screen they cost +0.04 to +0.42 ms. The real limit is spawn rate, about 120 per frame, not entity count. An isolated spawn attaches one frame later; bulk spawns attach in 1–3 frames (p50 43 ms).
  • Field note: collider gotchas.
    • A collider needs explicit filter masks: the “World Static” preset alone lets V fall through.
    • Pooled or moved colliders must be kinematic.
    • A collider can’t be resized after it attaches, but it can be sized at spawn (Entity/Initialize).
    • Merged 12 m boxes hold: a 12-block bridge with 11 seams had 0 frames with V off the surface.
  • Field note: one template, many looks. One entity template with one appearance per block “look” scales to 796 block types and 12k looks. Switching appearance resets the transform unless the mesh components are bound to a root placeholder with entHardTransformBinding.

Terrain goes back to Minecraft. The navmesh can’t be exported, so the district’s collision is voxelized offline into invisible barrier blocks in the MC world. Near the player, a live raycast grid (roughly 256–512 rays a frame) catches cars and moved props, and mob height snaps to the ground with a downward ray.

  • Field note: there is no “WolvenKit collision export” for most collision. This was the biggest unflagged risk in the plan. The WolvenKit 9 CLI can’t export cooked PhysX mesh geometry. Track D wrote its own parser for geometry_cache (cooked PhysX 3.4 meshes and convexes, 43,605 geometries) plus the terrain heightfields.
  • Field note: raycasts run native. A ray costs about 18 µs from CET Lua and about 4 µs from redscript.

Mobs are real Cyberpunk NPCs wearing Minecraft skins. TweakXL clones of NPC records use ArchiveXL meshes skinned to the base rig. The zombie is a fists brawler, and the skeleton is a ranged record with a bow reskin. The creeper is a script-driven puppet (move, fuse, explode), because four-legged custom rigs break when spawned. The precedent is Robot Kung-fu Bodyguards on 2.31. Mobs join a cloned hostile attitude group so gangs and NCPD fight them. Minecraft decides where a mob goes; the Cyberpunk puppet follows with move commands and snaps back if it drifts more than 1.5 m.

  • Field note: gangs fight mobs unprompted. Maelstrom engaged our mob in 5 of 5 trials with no scripted aggro.
  • Field note: attitudes need explicit records. A cloned attitude group registers at runtime, but its relations need explicit Attitude records; $base cloning doesn’t copy them.
  • Field note: staging scenes.
    • Sight ranges matter: zombies see 35 m, creepers 16 m, and both need line of sight.
    • One ganger can lose to a zombie, so stage a crew.
    • Persistent mobs in 26.x freeze after 5 s idle, which needed a patch.

Damage: one authority per path. The plan as first written could count creeper damage twice: MC forwarded damage to the fake players and CP spawned an explosion. The rule now:

  • Explosions: CP only. SpawnExplosionAttack damages NPCs and cars and never deforms the city; mob griefing is off in MC.
  • Mob attacks: MC only. Damage is forwarded to Cyberpunk, and the puppets’ own weapons are set to ×0 damage.
  • CP → MC: puppets are Immortal. A hit (OnDamageReceived, which fires and gives the exact damage) is scaled to 20 HP, sent over the bridge, and applied as Minecraft damage. The puppet is re-healed after every hit, because Immortal floors HP at 1 %, and a mob stuck at 1 % stops fighting. When the MC mob dies, CP calls Kill().
  • MC → CP: Cyberpunk NPCs are mirrored as Carpet fake players, because creepers only target players. MC cancels its own damage to them and forwards it.

The player. Steve’s first-person arms are a switchable garment. The held block is a fists-class item that reuses the vanilla swings. The hotbar and creative inventory are Codeware ink UI, prototyped in CET ImGui first. The block outline is a wireframe-cube entity, and creative flight is a noclip mode.

  • Field note: V exists in MC as a creative Carpet fake player, so items, block placement and useItemOn go through vanilla.
  • Field note: input conflicts. Keys 1–4 and the mouse wheel trigger weapon switching. Builder mode is an Input Loader context on an empty-hands NoCombat clone.

Redstone is not free. Minecraft runs the logic, but the bridge needs messages for interacting with blocks and for piston motion. Every block state also needs a generated look; redstone wire alone has 1,296 states.

Field note: things the first plan didn’t cover.

  • Time sync: CP’s time of day drives MC’s day and night, so natural night spawning works.
  • Sound: REDmod needs the DLC install, so sound goes through Audioware.
  • Saves: the MC world is the save, so builds persist through it.
  • Safety for your game: back up saves, watch autosave rotation, test that uninstall is clean, and check for regressions. Open bug: after the framework install, V appears unclothed in photo mode. The suspect is ArchiveXL’s PhotoModeScope.xl, and a bisect is in progress.

06Parallel tracks

The work splits into tracks that run at the same time, each with its own agent in its own git worktree and its own directory in one repo. Only one lane ever runs Cyberpunk. This is how the build actually ran: one orchestrator plus seven agents.

CONTRACT

Contract first: the bridge protocol. This is a small, versioned schema covering entity IDs, the per-tick snapshot fields, and events: block set/break/interact, piston motion, mob spawn/state, hit, death, explode, player state. It also defines a recorded-session format that any track can replay. It is written before the other tracks start, and any change to it is a pull request both sides sign off on. It went from v1.0 to v1.3 during the build.

The bridge can be proven without the game. A real Fabric server talks to the real Rust core over the bridge with the game layer stubbed out. That end-to-end test runs in CI on every change, so tracks A and B integrate continuously, long before Cyberpunk is involved.

What waits on what.

  • The spike and the protocol start together.
  • Tracks A, B’s bridge and interpolation work, D and E start at once.
  • B’s collider merging waits on spike answer 1, and C’s mob assets wait on answer 4.

I the only lane that runs the game

The integration lane. It owns the GPU, and is the one place work serializes. It runs the spike first. After that it takes merged work from the tracks, runs scripted scenarios through the CET console (spawn N blocks, stand V on a tower, drop a zombie next to a Maelstrom crew, detonate a creeper), and files failures back to the track that owns the code. An agent on your PC drives this lane, so you play-test milestones for feel rather than being the test harness.

08Spike: the six unknowns, answered

  1. Does V stand on runtime box colliders, and what do blocks cost with path tracing?

    Yes, including merged 12 m boxes. Blocks are nearly free: on screen they lower frame time, and off screen they cost under half a millisecond.

  2. How long does an async spawn take, and does pooling hide it?

    One frame isolated, 1–3 frames in bulk (p50 43 ms). Spawn rate, about 120 per frame, is the real limit.

  3. Do hit events fire on a god-moded NPC?

    Yes. Under Immortal, OnDamageReceived gives the exact damage.

  4. Do gangs fight reskinned mobs?

    Yes, 5 of 5 trials, with no scripted aggro.

  5. Does a cloned attitude group register at runtime?

    Yes, but its relations need explicit Attitude records.

  6. What does the raycast grid cost, and does voxelization scale?

    About 4 µs per ray from redscript (18 µs from CET Lua), so it runs native. All of Northside voxelizes in 152 s.

09Hard limits

  • The navmesh is baked. Cyberpunk NPCs never walk onto your builds; mobs climbing towers has to come from Minecraft’s pathing.
  • No new first-person animation sets, only replacements, so Steve’s swing is V’s swing re-skinned.
  • NCPD heat only counts damage V deals. Police responding to a creeper has to be scripted.
  • Night City can’t be mined. The city’s own geometry stays; only placed blocks break.

10Setup on your PC

Cyberpunk 2077 2.31 (Steam or GOG) with Cyber Engine Tweaks 1.37.1, RED4ext 1.30, redscript 0.5.31, Codeware 1.20.5, TweakXL, ArchiveXL, Input Loader, Audioware, and WolvenKit 9.0.1 with the .NET 10 runtime. Also:

  • a Rust MSVC toolchain, LLVM/libclang ≤ 21 (with libclang 22 or later, red4ext-rs’s bindgen silently generates empty structs) and CMake;
  • Java 25;
  • a Fabric server pinned to Minecraft 26.3 with Carpet. 26.x ships unobfuscated, which changes the Loom setup.

Minecraft textures and the server jar are pulled from your own Minecraft install or Mojang on first run, so nothing Mojang owns ships with the mod. Stay non-commercial. Back up your saves before the first install.

Run one Claude Code agent per track, each in its own git worktree, with this plan as the shared brief; only the integration agent launches the game. The integration lane has to be your PC. You play-test each milestone for feel.
