01The five things that will trip a Python person

  1. <- is assignment. x <- 5 means x = 5. (= also works at the top level, but the tidyverse world uses <-, and inside a function call = names an argument.)
  2. Nothing changes in place. df %>% filter(...) returns a new table and prints it. If you don't assign it with <-, it's gone. This is the single most common lab bug, and it's in this lab (Q2).
  3. Everything is a vector, and it's 1-indexed. There are no scalars: 5 is a vector of length 1. x[1] is the first element. Comparisons work element-wise, like numpy.
  4. NA is contagious. Any calculation touching an NA returns NA: max(), mean(), sum(). You opt out with na.rm = TRUE or by filtering first (Q3).
  5. Bare column names. Inside dplyr verbs you write filter(year_signed > 1972), not df["year_signed"]. dplyr looks the names up in the table for you ("data masking").

03Quarto: the .qmd file

A .qmd file is a Jupyter notebook written as plain text. Prose is Markdown, and code lives in chunks that open with ```{r} and close with ```. Render runs every chunk top to bottom in a fresh R session and produces the HTML file the student uploads.

  • Only what's inside a chunk runs. Code outside a chunk is just text in the HTML. (Q4 has a pipeline sitting outside its chunk.)
  • Fresh session, in order. If a chunk uses a name defined in a later chunk, or a name that was only ever typed in the console, Render fails even though it "worked" interactively. When Render breaks, restart R and run all chunks in order to reproduce it.
  • The last value of a chunk prints. Like a notebook cell, the last expression's value prints. So does any un-assigned expression in the middle of a chunk.

04Tibbles and the pipe

A tibble is the tidyverse's DataFrame. Printing one shows its size and each column's type under its name: <chr> string, <dbl> float, <int> integer, <lgl> boolean. It shows only the first rows, and only as many columns as fit, then says how many it skipped.

The pipe %>% feeds the thing on its left in as the first argument of the function on its right. Read it as "and then". It's pandas method-chaining, with functions instead of methods. Newer R also has a built-in |> that does the same job for this lab.

Nothing is modified in place. A pipeline returns a new tibble and prints it if you don't assign it. To keep it, assign it.

06NA, the contagious value

R's NA covers pandas' NaN, None and pd.NA all at once, and it spreads through calculations unless you say otherwise:

Two idioms do most of the NA work in this lab. The first is filter(!is.na(x)), which drops the missing rows before calculating. The second relies on TRUE counting as 1, so sum(is.na(x)) counts the missing values and mean(is.na(x)) gives the share that's missing. 07Grouping: summarise collapses, mutate keeps every row

This is the idea the second half of the lab turns on. group_by() doesn't change anything you can see; it marks the table so the next verb works one group at a time. What happens next depends on the verb:

  • summarise() collapses each group to one row, like pandas .agg().
  • mutate() keeps every row and writes the group's value onto each one, like pandas .transform().

Group by two columns and summarise peels off only the last one. The result is still grouped by the first, and dplyr prints a message to say so. It's a message, not an error. If the leftover grouping gets in the way later, add %>% ungroup() or pass .groups = "drop". Note the # Groups: line in this output:

08The lab, question by question

The data: iea_agreements.csv has 5,016 international environmental agreements, one per row. The columns that matter are year_signed, subject (11 issue areas), scope (Bilateral, Multilateral or Other), year_in_force and n_members. n_members is NA for 1,556 agreements, those with no entry-into-force record, and year_in_force is NA for 1,495, mostly bilateral (codebook). Those two NA counts are nearly the same size, which is the clue for Q4.

This is the filter(!is.na()) %>% group_by() %>% summarise(max()) %>% arrange(desc()) pattern from §07, and the logic is right. Two small things. The task asks for biggest_agreements with an s, and the draft names it biggest_agreement. And the task says to look at the largest and smallest, so also view it with arrange(max_members), or tail(). The "grouped output" message is expected.

Q4 · Where are the NAs? open-ended

The chunk's group_by(scope) %>% summarise(n(), sum(is.na()), mean(is.na())) is exactly the §06 idiom. The second attempt, filter(is.na(n_members)) %>% count(scope, sort = TRUE), is also a good move, but it sits outside the chunk, with its notes written as -keeps rows…. R comments start with #. Pasted into a chunk as-is, it fails before running:

Ideas to explore: repeat the summary by subject, instrument and decade (mutate(decade = year_signed %/% 10 * 10)). Then run the same breakdown on year_in_force and compare. Why might they match? In the codebook, n_members counts countries for which the agreement entered into force, so an agreement with no entry-into-force record has neither.

Q5 · Average members per subject + scope, on every row to do

This is the mutate-after-group_by pattern from §07, not summarise. The task wants the average written onto every row, so the table keeps its rows. In pandas terms it's transform, not agg. The shape is: drop the NA rows, group by both columns, mutate a mean column, ungroup(), then select() the five columns, and assign it to agreements_avg_members. The starwars example in §07 is the same shape with one grouping column instead of two.

Q6 · Flag above-average rows to do

One more mutate: compare the row's n_members with the average column from Q5. The comparison itself is the TRUE/FALSE column, so no if or ifelse is needed. See the last example in §07.
