Finding The roles are not enforced

The brief for this report assumed each role receives different prose. It does not. The system prompt is byte-identical for every role — nothing in buildSystemPrompt() takes a role, and nothing in 495 lines branches on one.

Every agent can read every role's paragraph, including its own restrictions and everyone else's. The prompt says this about itself: holding Discord is "a RULE AND NOT A GATE", and nothing in the code checks a role before a Discord post.

The gap What is running is not what is on main

Measured rather than described, by parsing the prompt out of both revisions.

The 51 lines are credential handling. Running agents have not been told that -v, --trace and --trace-ascii print the Authorization header, which is the credential; that only curl reads the netrc; that it matches api.github.com and no other host; or the core.limit test for whether anything was sent. This is not a documentation lag.

What this page cannot establish. The deployed commit is pinned to a revision whose prompt matches e8d1c5a's, not to that commit exactly — any commit between it and #205 that did not touch the prompt is indistinguishable from here. Settling it needs the build banner or git rev-parse HEAD on the host. Likewise the base preset text beyond its first sentence: it lives inside a 275 MB binary and is assembled per run, and pulling more static strings out would yield fragments nobody here could order or attribute — a claim wearing the shape of a map.

Finding "Every string the agent sees lives in prompts"

src/prompt.ts:4-8 states that rule about itself. It is true of that file and false of the system: two whole templates are code literals (mailWake, spawnCharter), one user-visible string is a literal in src/daemon.ts:345, and four documented placeholders are computed and discarded. Filed as #226; five stale file:line citations inside the prompt itself are #225.
